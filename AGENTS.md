# AGENTS.md — Румикуб (многопользовательская игра)

Этот файл — источник общей информации о проекте. Читай его в начале работы и обращайся к нему при любых вопросах о структуре, правилах и конвенциях, чтобы не переспрашивать.

## Что это

Многопользовательский **Румикуб** (Rummikub):

- **React (Vite)** — клиент, красивое тёмное UI.
- **Node.js + Express + Socket.io** — сервер, источник правды (authoritative server).
- Игра с друзьями **по коду комнаты** (до 4 человек) либо **с компьютерными соперниками** (боты).
- Один процесс на сервере: в production Node раздаёт собранный клиент (`client/dist`) и обслуживает WebSocket на том же порту.

## Быстрый старт

```bash
npm install            # установит зависимости корня и клиента (postinstall)
npm run dev            # dev: сервер :3001 + Vite :5173 (прокси /socket.io)
npm run build          # собрать клиент в client/dist
npm start              # production-сервер (PORT по умолчанию 3001, NODE_ENV=production)
npm run check          # собрать клиент + прогнать логические тесты
```

Деплой (любой вариант):

```bash
# Вариант 1: Docker
docker build -t rummikub .
docker run -p 3001:3001 -e PORT=3001 rummikub

# Вариант 2: Node напрямую
npm ci && npm run build && NODE_ENV=production PORT=3001 node server/src/index.js
```

Друзья подключаются по `http://<адрес сервера>:3001`. Снаружи достаточно открыть один порт (http + WebSocket). Для публичного сервера желателен reverse-proxy с TLS (WebSocket работает поверх http).

## Архитектура

```

  src/App.jsx               переключение экранов: Home → Room → Game
  src/lib/socket.js         тонкая обёртка над socket.io-client (emit с ack)
  src/lib/melds.js          правила: валидация групп + стоимость фишек
  src/components/           Home, Room, Game, Tile
  src/styles.css            вся стилизация (тёмная тема, фишки, кнопки)
server/                     Node.js, ESM
  src/index.js              Socket.io-обработчики, комнаты, раздача статики
  src/game/game.js          игровое состояние и правила (ход/выкладка/взятие/победа)
  src/game/melds.js         правила: валидация групп + колода/цвета/стоимость (общая точка истины)
  src/game/ai.js            боты: подбор комбинаций, принятие решений
  test/run-tests.mjs        логические тесты правил
Dockerfile                  сборка и запуск в контейнере

**Важно:** `melds.js` намеренно продублирован в `server/src/game/` и `client/src/lib/`
(в клиенте — те же `isValidMeld`, `tilePoints`, цвета). При изменении правил меняй **оба**
файла идентично: сервер валидирует ходы, клиент использует его для живой подсветки групп.

## Правила Румикуба (реализованные)

- **Фишки:** 106 (4 цвета × 13 чисел × 2 копии + 2 джокера). Джокер заменяет любую фишку, стоит 30 очков.
- **Группы (комбинации):**
  - *Сет*: 3–4 фишки одного числа, все разных цветов.
  - *Серия*: 3+ фишки подряд одного цвета (в пределах 1–13).
  - Джокер может «дополнить» сет/серию. См. `isValidMeld`.
- **Ход:**
  - Игрок набирает 14 фишек; ход — по очереди.
  - **Первая выкладка** должна набирать **минимум 30 очков** фишками с руки (проверяется на сервере).
  - После первого захода можно свободно манипулировать столом: добавлять свои фишки в существующие группы, собирать новые, перекладывать фишки стола между группами.
  - **«Сыграть»** — отправить итоговую расстановку стола. Сервер валидирует: все группы корректны, фишки стола не потеряны/не добавлены чужие, с руки выложено ≥1 фишки, первый заход ≥30.
  - **«Взять фишку»** — если не можешь сыграть; берётся из колоды и ход передаётся дальше. После взятия в этом ходу нельзя сыграть.
  - Победа — при пустой руке после выкладки. Очки: победитель получает сумму штрафов соперников, соперники — минус сумма очков своей руки (джокер = 30).
- **Отключение игрока** во время партии: его заменяет автопилот (бот играет за него). В лобби отключение просто удаляет игрока.
- **Боты:** различаются уровнем сложности (`easy`/`medium`/`hard`) — вероятностью «пройти» ход вместо оптимального.

## Сетевой протокол (Socket.io)

Клиент → сервер (с ack-колбэком `{ok, error?, ...}`):

- `room:create {id, name, addBot, difficulty, color, emoji}` — создать комнату (host).
- `room:join {code, name, id, color, emoji}` — присоединиться по коду.
- `room:rejoin {code, id, name, color, emoji}` — восстановить сессию после обновления страницы (всегда передаётся при загрузке, если сохранена сессия).
- `room:addBot` / `room:removeBot botId` / `room:setDifficulty d` — управление комнатой (host, только в лобби).
- `room:start` — начать игру (host, минимум 2 игрока).
- `game:play {board}` — применить итоговую расстановку стола.
- `game:draw` — взять фишку.
- `game:end` — досрочно завершить игру (host): без победителя и без начисления очков за партию.
- `leaderboard:get` — получить таблицу лидеров сервера (top-50 по накопленным очкам, только живые игроки; боты не учитываются).
- `room:leave` — покинуть комнату.

**Идентичность игрока:** `id` — стабильный идентификатор, который клиент генерирует
и хранит в localStorage (`rummi-player-id`); он переживает обновление страницы. Сервер
санитизирует его до `[a-zA-Z0-9]{1,24}`. Внутри комнаты игрок ищется по этому `id`,
`socketId` — лишь текущий живой сокет. При обрыве соединения игрок не удаляется сразу:
сервер ждёт `RECONNECT_GRACE_MS` (8 c), затем в лобби удаляет, во время игры включает автопилот.

Сервер → клиент:

- `room` — **полный снимок комнаты** (персонализированный: `game.you.hand` — только своя рука; у соперников только количество фишек). Это единственный канал состояния; клиент ничего не хранит.
- `error` — короткое сообщение об ошибке (тост).

Формат снимка (`room`):

```ts
{
  code, status: 'lobby'|'playing', hostId,
  settings: { difficulty },
  players: [{ id, name, ai, color, emoji, connected }],
  game: null | {
    phase: 'playing'|'ended', winnerId, turnIndex, gameId,
    board: Tile[][],            // группы на столе
    stockCount, log: string[],
    played: [{ id, name, color, emoji, tileIds: number[] }], // последние выложенные фишки каждого игрока (хранятся, пока игрок не сыграет новые)
    players: [{ id, name, ai, color, emoji, handCount, melded, score, total }],
    you: { hand: Tile[], melded, drew, yourTurn } | null,
  }
}
```

`gameId` — монотонно растущий номер партии в комнате.

`Tile = { id: number, color: 'R'|'B'|'K'|'Y'|'JOKER', value: 1..13|0 }`.

**Профиль игрока:** `color` (hex из палитры) и `emoji` (зверь из списка) клиент хранит
в localStorage (`rummi-profile`) и передаёт при create/join/rejoin; сервер валидирует
по белому списку (палитры в `server/src/index.js`), боты получают цвет/смайл автоматически.

**Как работают ходы:** на клиенте во время своего хода игрок свободно редактирует локальную копию стола (клик по фишке = выбор; «Новая группа», «+» на группе, «Сброс»). При «Сыграть» отправляется итоговый `board`, сервер валидирует целиком и рассылает новый снимок всем. Сервер **не** валидирует промежуточные манипуляции — только финальное состояние.

## Конвенции кода

- **ESM** (`"type": "module"`) везде; импорты с расширениями `.js`/`.jsx`.
- **React 18**, хуки, функциональные компоненты. Без сторонних UI-библиотек.
- **Комментарии** — только там, где логика неочевидна; не комментируй очевидное.
- **UI на русском языке**.
- Имена на английском, строки интерфейса — на русском.
- Стили — только в `client/src/styles.css`, классы в kebab-case.
- Не вводить тяжёлых зависимостей без необходимости: деплой максимально простой.
- Ключи снимков и событий менять аккуратно: клиент и сервер связаны жёстко.

## Очки

- **За партию** (`game.players[].score`) считает сервер при завершении (победа/досрочно) и отдаёт в снимке.
- **Накопленные очки** начисляет сервер при завершении партии (однократно за `gameId`, `settleGame()` в `server/src/index.js`) в общую копилку `cumulativeScores` и отдаёт каждому игроку в снимке как `players[].total` (и в лобби, и в игре). Клиент только отображает `p.total` — refresh/повторный снимок не приводят к повторному начислению.

## Типовые задачи и где что менять

- **Правила/валидация** → `server/src/game/melds.js` + `client/src/lib/melds.js` (синхронно), `server/src/game/game.js`.
- **Поведение ботов** → `server/src/game/ai.js` (уровни сложности — в `aiDecision`, `passChance`).
- **Новые экраны/элементы UI** → `client/src/components/`, разметка в JSX, стили в `styles.css`.
- **Новые события/данные снимка** → обработчики в `server/src/index.js` + `snapshot()`, эмиты в `client/src/lib/socket.js` и `App.jsx`.
- **Развёртывание** → `Dockerfile`, скрипты в корневом `package.json`.

## Известные упрощения (не «баги», осознанный scope)

- Нет таймера хода (ожидание живого игрока бесконечное, если он не отключился).
- Взятая фишка сразу попадает в руку (в правилах может лежать «в отложенных» перед игроком).
- Нет чата.
- Бот не использует джокеры при «построении» новых групп с нуля (только для дополнения существующих).
- Две вкладки с одним `rummi-player-id` считаются одним игроком (последняя активная).
